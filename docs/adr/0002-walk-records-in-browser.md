# ADR 0002: 歩いた記録はブラウザに保存し、DB（Firestore）は使わない

- 状態: 採用（2026-11-07）
- 決めた人: サーバー担当・画面担当

## 背景

散歩ごとの記録（いつ・どの気分で・どの場所に着いたか・その場所へのメモ）を残したい。
また、「この場所に何回来たか」を数えたり、行ったことのある場所をルートの候補から外したりしたい。

画面担当がすでに、ブラウザの localStorage に記録を保存する形で実装している。
サーバー側でも、Firestoreに保存するAPIを試作した経緯がある。現在のツリーには `api/store.py` も `/api/walks`・`/api/comments` の登録もない。

## 検討した案

| 案 | 内容 | できること | できないこと・負担 |
|---|---|---|---|
| A. ブラウザに保存（localStorage） | 記録は端末の中だけ。サーバーに送らない | 記録・メモ・日付ごとの履歴・訪問回数・行った場所の除外 | 端末をまたげない。ブラウザの保存方針やサイトデータ削除で消える場合がある |
| B. Firestore（ブラウザごとのランダム ID） | 記録をサーバーにも送る | A に加えて、端末の外に残る | ログインがないので、ID を知られると読める。保存と同意の説明が増える |
| C. Firestore ＋ Firebase の匿名ログイン | B を本物の認証で守る | B の弱点を解消 | 画面とサーバーの両方の作業が大きい |

## 決定

**A を採用する。** 訪問回数も、ブラウザの記録から画面側で数える。

## 理由

1. **やりたいことは A で全部できる。** 記録・メモ・訪問回数・行った場所の除外は、本人の記録だけで計算できる。DB に置いても計算の中身は変わらない。
2. **位置に関わるデータを外に出さない。** 記録には訪れた場所・時刻・歩いた道（現在地の履歴）が入る。端末の中に置けば、サーバーからの漏えいという経路がない。サーバーは出発地をルート作成に使うが、散歩記録用のDBや永続保存APIを持たない。Placesの照会結果や回数制限はプロセス内メモリに保持する。

（追記 2026-11-08）歩いた道もブラウザに保存できるようにした。ただし出発地は自宅であることが多く、歩いた道には自宅の位置が含まれうるため、次のように制限した（詳細は [web/TRACKING.md](../../web/TRACKING.md)）。

- 出発前の保存チェックは初期値オン。外すと位置履歴と日記を保存しない。記録だけを途中で止める操作はなく、散歩の終了で停止する。日記から個別／一括削除できる
- 位置の点列に保存するのは緯度・経度・精度・時刻の4項目だけ。サーバーには送らない（区間のID・状態等は別に保持する）
- 7日より古いものは、アプリを開いたときに整理して消す。全体で最大20区間・6,000点まで（再開時は別区間）

現在の実装には、日記・位置履歴とは別に途中再開用の `yorimichi:active` がある。
保存チェックを外しても出発地・ルート・気分・訪問内容などを一時保存する。12時間経過後の次の読込時、または散歩終了・新規開始時に破棄する。
これは「何も保存しない」動作ではない。保存項目は [ルートREADME](../../README.md#保存とプライバシー)、再開手順は [web/RESTART.md](../../web/RESTART.md) を参照。

3. **DB が本当に意味を持つのは「みんなの記録をまとめる」ときだが、今は使う人がいない。** 締切までに集まるデータは開発者の数回分で、集計しても中身がない。他人の行動を集めるには、何を集めて何に使うかの説明と同意も必要になる。
4. **締切（2026-11-10）までの時間を、デモと完成度に回す。**

## 結果

- 記録は「同じ端末・同じブラウザで使い続ける限り残る」保存になる。デモでは同じ端末を使う。
- 画面の説明文では「記録はこのブラウザにだけ保存されます」と明記する（実際の動きと一致させる）。
- 試作した `api/store.py` と記録用APIは現在のツリーに存在しない。配信されるのは `api/main.py` のhealth・clarify・routeと静的画面。
- 将来 DB を入れる条件：
  - **人の集中を分散させる**：最近多く訪れられた場所を候補から外す。「知らない場所に出会う」という目的に沿う、DB を使う一番の理由。
  - 端末をまたいで記録を見たい要望が出たとき。
  - そのときは C（匿名ログイン）で守り、集める項目と用途を画面で説明して同意を取る。
