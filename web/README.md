# よりみち — 画面開発ガイド

`web/` はビルド不要のHTML/CSS/JavaScriptです。全体構成・サーバー設定・API・Cloud Run手順は [ルートREADME](../README.md) を参照してください。
この文書は画面開発と手動確認に絞ります。ZIP配置や特定メンバーのブランチを前提にした手順は不要です。

## 見本で動かす

リポジトリ直下から実行します。

```bash
python3 -m http.server 8503 --bind 127.0.0.1 --directory web
```

[http://localhost:8503/?mock=1](http://localhost:8503/?mock=1) を開きます。終了はControl+C。
`file://` ではなくHTTPで開いてください。

見本は `mock/clarify.json` と `mock/route.json` を読みます。Gemini・Places・Routes・自分たちのAPIは呼びません。
**Mapsキーが設定済みなら、見本でもGoogleマップを読み込みます。** 未設定／読込失敗時は模式図です。
外部APIなしで確認するときはブラウザ用キーを設定しないでください。
見本の地点・OSM ID・線は操作確認用で、現地調査やRoutes APIの実結果ではありません。
気分や出発地を変えても地点は固定です。「外す」は見本のIDを除去します。

## Googleマップと実APIに接続する

1. リポジトリ直下で `cp web/config.example.js web/config.js` を実行する。
2. `window.MAPS_JS_API_KEY` にブラウザ用キーを設定する。Maps JavaScript APIへのAPI制限と、開発URL・公開URLのウェブサイト制限を設定する。
3. [通常モードの起動手順](../README.md#通常モードをローカルで動かす) でFastAPIを起動し、[http://localhost:8080](http://localhost:8080) を `?mock=1` なしで開く。

通常モードは `/api/clarify` と `/api/route` を同一オリジンで呼びます。上の静的サーバーだけでは実APIは動きません。
FastAPIには `web/` の配信が実装済みです。
`config.js` はGit管理外。Places・Routes用のサーバーキーやGeminiの秘密キーは書かないでください。
Cloud Runへの同梱方法は [ルートREADME](../README.md#cloud-runへのデプロイ) に集約しています。

Googleマップのgeometryライブラリでpolylineを復号し、線とピンを表示します。
通常モードで地図が読み込めない場合は場所一覧を隠してエラーを表示します。
歩行中は現在地マーカーを更新します。表示する距離はルートに沿った距離を基本とし、線から離れると直線の目安へ切り替えます。

## 現在の画面と操作

- 初回注意 → 気分 → 1回の聞き返し（選択肢／自由記述／おまかせ）→ 時間・出発地 → ルート。
- 場所をOSM IDで除外して再検索。画面は `include_ids: []` を送る。
- API待機は経過秒数、キャンセル、65秒のタイムアウト、429などのエラーを表示。
- `blocked.message` があれば他の結果・操作を表示しない。
- 歩行 → 本人が「着いた」→ 任意メモ → 記録して次へ／記録せず次へ → 完了。5段階評価はない。
- 散歩日記・足あとマップ、個別／一括削除、途中終了、新しい散歩、途中状態からの再開。

位置情報はlocalhostまたはHTTPSで試します。スマホからPCのHTTPのLANアドレスで開くと、位置情報を利用できないことがあります。
見本は歩行開始時に自動でGPSを要求しません。「この場所への到着を再現」や「現在地で到着判定を試す」を使えます。
精度50m以内・取得から30秒以内の位置が目的地から50m以内なら近接を知らせますが、**自動で到着扱いにはしません**。「着いた」で進みます。
拒否・精度不足時も手動で進めます。到着・終了・ページ離脱時に位置監視を止め、次の場所へ歩くと再開します。
画面ロック中・バックグラウンドの位置取得は保証しません。

## 保存と再開

保存項目の一覧と通信先は [ルートREADME](../README.md#保存とプライバシー)、位置履歴の品質と上限は [TRACKING.md](TRACKING.md)、終了・再開は [RESTART.md](RESTART.md) を参照してください。

「歩いた道と記録を保存する」は初期値オンです。外すと日記と位置履歴は保存しませんが、**途中再開用 `yorimichi:active` は別に保存され、出発地・ルート・気分などを含みます**。
再開用状態は12時間で読込対象外になります。散歩・GPSは利用者が再開ボタンを押すまで再開しません。
localhostと127.0.0.1、ポート違い、公開URLでは保存内容は別になります。

## ファイルの役割

- `index.html`：共通の枠、アプリ紹介。
- `style.css`：スマートフォンとPCの表示。
- `app.js`：画面遷移、API・地図・GPS接続、日記、再開状態。
- `storage.js`：位置履歴のlocalStorage読書き、整形、期限・保存量の制限。
- `tracking.js`：GPS点の選別、記録開始・終了。
- `mock/*.json`：API応答の固定見本。
- `config.example.js`：ブラウザ用設定のひな形。
- `tests/*.test.mjs`：仮の位置データと最小DOMによる試験。

## 確認手順

リポジトリ直下で、Node.jsのテストランナーを使います（npmの導入・ビルドは不要）。

```bash
node --test web/tests/tracking.test.mjs web/tests/walk-restart.test.mjs
```

手動では次を確認してください。

1. キーなしの見本で、気分入力から完了、除外・再検索、途中終了・新しい散歩、日記の削除まで進む。
2. 保存オン／オフで日記・位置履歴と再開用状態の違いを確認する。再読込後の再開・終了も確認する。
3. 375px幅とPC幅で描画・操作を確認する。
4. Chromeの開発者ツール → More tools → Sensorsで目的地付近に位置を更新し、近接通知と手動到着を確認する。見本の最初の場所は緯度 `34.9921`、経度 `135.7869`。
5. 通常モードで実API・Googleマップ表示、HTTPSのスマートフォンで位置許可・拒否・歩行を確認する。

自動試験は実API、実ブラウザの描画、実GPSを使いません。これらの実接続を確認済みとは扱わないでください。

## 変更を共有する

作業内容に合ったブランチで変更し、`git status` と `git diff -- web/` で確認します。
コミット前に `git diff --cached --name-only` で、`web/config.js`、`.env`、場所データが含まれていないことを確認してください。
APIの変更が必要なら [api/main.py](../api/main.py) と画面を合わせ、ルートREADMEも更新します。
