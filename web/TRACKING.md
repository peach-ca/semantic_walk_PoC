# フロント側の位置履歴

サーバー側/API側は変更しません。既存の訪問場所・メモの記録と、移動中の位置履歴を分けます。

## 操作

1. ルート画面の「歩いた道と記録をこのブラウザに保存する」は、最初からチェックが入っています（新しく散歩を始めるたびにオンに戻ります）。保存したくない場合はチェックを外します。外した場合は、位置履歴だけでなく、立ち寄った場所・メモ（`yorimichi:walks`）も保存しません。
2. 「歩きはじめる」から、既存のwatchPositionで受け取るGPS更新を記録します。
3. 歩いた道は、歩行中の地図に青い線でその場で描かれます。記録中の表示は出さず、保存できないときや上限に達したときだけ知らせます。散歩の途中で記録だけを止めることはできません（記録しない場合は、歩き始める前にチェックを外します）。
4. 「散歩日記」の各散歩に、時間と歩いた距離の目安を並べて表示します。ホームの「足あとマップ」から、保存した道をすべて地図に重ねて見られます（一番新しい道は濃い緑、立ち寄った場所は白い点）。キーのない見本モードでは、地図の代わりに道だけを図にします。
5. 「散歩日記」の画面で、散歩ごとに「この記録を消す」、またはまとめて「散歩日記をすべて消す」で削除できます。どちらも、その散歩の歩いた道も一緒に消します。

次の場所から50m以内に来ると「〇〇のそばに来ました」と知らせます。自動では進まず、本人が「着いた」を押します。到着時はGPS取得を止め、振り返り後に次の場所へ歩くと再開します。
画面を閉じると位置取得を止め、取得済みの履歴を中断として残します。
ページ再読み込み後も記録は残りますが、散歩・位置追跡は自動再開しません。
スマホの画面ロック中やバックグラウンドでは、ブラウザ・OSにより位置取得が止まることがあります。

## 歩行中の地図の線

- ルートのうち通ったところは薄い色、これからの道は緑で表示します。現在地をルートの線に重ね、線から60m以内のときだけ進んだことにします。着いた場所までは通ったことにします。
- 地図右上の「過去の道」を押すと、保存した過去の道（今歩いている散歩の分は除く）をうっすら重ねます。もう一度押すと消えます。オン・オフは `yorimichi:showPast` に覚えます。保存した道がないときはボタンを出しません。
- 自分が実際に歩いた線を青で重ねます。この線は画面表示のためだけに使い、保存の選択に関係なく保存しません。
- 次の場所までの距離は、ルートの線に沿った道のりです。線から離れているときは直線の距離に切り替え、「直線の目安」と表示します。

## 途切れた区間

画面を消していた間や、ブラウザを閉じていた間は位置が取れません。前の位置から2分半以上あいたら、そこで線を切り、地図ではつながず、距離にも足しません（`splitTrack`、`trackLength`）。立ち止まっている間の記録は最長60秒おきなので、休憩しているだけでは切れません。

## 保存データ

localStorageの `yorimichi:tracks:v1` に、散歩ID、開始・終了時刻、状態、見本モードの区別と、以下の点列を保存します。

```json
{
  "lat": 35.0085,
  "lon": 135.7485,
  "accuracy": 12.3,
  "timestamp": 1800000000000
}
```

`timestamp`は位置が取得された時刻（Unixミリ秒）、`accuracy`はブラウザが返した位置精度の目安（m）です。
Googleの施設情報、AIの回答、APIキーは位置履歴に含めません。
新しい保存処理から自分たちのサーバーへ送信することはありません。
地図表示に使うGoogle SDKの通信は既存どおりです。

## 保存量・品質の制限

- 精度100m以内、取得から30秒以内の点のみ。
- 連続する記録は最短10秒。5m未満の移動は最短60秒。
- 1回最大1,200点。到達すると保存を止め、案内は継続します。
- 全体で最大20回・6,000点。古い散歩から整理します。
- 最大7日間。削除はアプリを開いたとき／保存時の整理によるもので、アプリを閉じている間にタイマーで自動削除するものではありません。
- 保存禁止・容量不足の場合はメッセージを表示して保存を止めます。位置表示・散歩操作は継続できます。

Chromeの開発者ツール（Mac: ⌘+Option+I）→ Application → Local Storage → 開いているURL → `yorimichi:tracks:v1`でも内容を確認できます。
localStorageは端末・ブラウザ・オリジンごとに別です。localhostと127.0.0.1、異なるポート、公開URLでは履歴を共有しません。
プライベートブラウズやサイトデータの削除では履歴が消える場合があります。恒久保存・暗号化された保管庫ではありません。

## ファイルと確認

- tracking.js: 点の選別、記録の開始・停止、削除時の書き込み停止
- storage.js: localStorageの読み書き、必要な項目への整形、保存量と期限の整理
- app.js: チェックボックス・状態・履歴表示、既存GPSコールバックからの接続
- tests/tracking.test.mjs: 外部通信なしの確認

```bash
node --test web/tests/tracking.test.mjs
```

見本で到着操作だけを行ってもGPS点は増えません。位置保存の実機確認は保存を選択し、位置情報を許可して、実際に歩くかChrome Sensorsで位置を更新して行います。

現在地の取得・保存にGemini/OpenAIは不要です。ただし、既存の見本モードはGoogleマップのキーが設定されているとGoogleマップを読み込む実装です。アプリ全体が完全に外部APIを呼ばないことを意味しません。
