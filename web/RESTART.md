# 途中で散歩を終了して、新しい散歩を始める

## 動作

1. 歩行中の「散歩を切り上げる」、または左上の「よりみち」を押す。
2. 終了確認でキャンセルすると、現在の散歩を継続。振り返りの入力中メモもそのまま残る。
3. 終了すると位置追跡を止める。保存を選んでいた場合は開始・終了時刻、実際の経過秒数、保存済みの訪問場所・メモを保存する。
4. 移動中の位置履歴は、出発時に保存を選んでいた場合のみ残す。記録の状態はstopped。
5. 保存を選んでいれば、未訪問でも1回の散歩として記録。未到着の場所は訪問済みにしない。振り返り画面で未送信のメモは保存しない旨を終了確認に表示する。
6. 「現在地から新しく歩く」または「今日は終える」を選ぶ。
7. 新しく歩く場合は気分入力画面へ。気分、選択肢、予定時間、ルートをリセットし、以前の記録は消さない。時間の初期値は45分で、準備画面で「これから歩く時間」として選び直す。
8. 新しい出発地は30秒以内の直近の実位置を使う。実位置がなければ1回取得する。取得できなくても進めるが、準備画面で出発地を確認・変更するよう案内する。
9. 新しい散歩は別IDで記録。歩いた道と記録の保存は新しい散歩ごとに選択する（初期値オン）。

「今日は終える」は終了画面へ進む。途中終了と、すべて歩き終えた場合のどちらも記録を削除しない。
保存エラーは表示し、未保存の記録がある場合は画面を閉じると失われる可能性を伝える。

## 再読込・終了後に続きから歩く

現在の実装は、歩行・振り返り画面の状態をlocalStorageの `yorimichi:active` に保存します。
同じオリジン・同じ見本／通常モードで12時間以内に開き直すと、「続きから歩く」「この散歩を終える」を選べます。
自動ではGPSを再開せず、歩行画面からの再開を選んだときに位置監視を開始します。
位置履歴の保存を選んでいた場合は、再開後を別区間IDとして記録します。

一時状態は日記・位置履歴の保存チェックを外しても保存され、出発地・気分・ルート・訪問内容を含みます。
`maps_uri` は除きますが、polylineや地点情報は含みます。12時間は次の読込時の有効期限判定で、閉じている間の自動削除ではありません。
散歩の終了・新規開始時に一時状態を消します。詳細な保存一覧は [ルートREADME](../README.md#保存とプライバシー) を参照してください。
振り返り欄でまだ記録していない入力中メモは再開用状態には含みません。

## 記録

`yorimichi:walks`に以下を追加：

- status: completed / stopped / interrupted
- elapsed_seconds: 開始から終了までの実経過秒数（休憩も含む）。予定時間minutesとは別。

移動履歴は従来どおり`yorimichi:tracks:v1`。サーバーへ送信する機能は追加しない。

## 見本と試験

ロゴのリンクはmock=1の指定を維持する。通常クリックはページを再読込せずに処理する。
Command/Ctrlクリックなど、新しいタブで開く操作は通常のリンク動作を維持する。

```bash
node --test web/tests/tracking.test.mjs web/tests/walk-restart.test.mjs
```

新しい試験はブラウザ操作を模した最小DOMと仮の位置データを使う。Google・GeminiのAPIや実GPSは使わない。
終了などの確認は、ブラウザの確認ダイアログではなくアプリの画面の中で表示する。実ブラウザの描画、スマホの位置取得は別途手元で確認する。
